# LineCode 专业模式教程

> 这份教程适合已经上手、想"用得更狠"的高级用户——讲的是怎么高效地让 AI 帮你改代码。如果你只想看基本用法，请切到"简单模式"。

---

## 1. 项目与多工作区

### 多项目并行

- 同一时间只能有一个"当前项目"，但**项目列表**可以保留多个：点击聊天顶部项目名即可切换，或从左侧抽屉进入。
- 切换项目时：所有文件工具、Shell、Agent 的工作目录会**整体迁移**到新项目；未保存的草稿消息不会丢。
- 适合场景：一个项目写业务代码、另一个项目放参考实现、第三个项目做脚本工具。**不要把多个 Git 仓库混在同一个项目里**——后续归档、SSH 转发都会出问题。

### 项目来源

| 类型 | 特点 |
| --- | --- |
| 打开本地项目（SAF） | 真实项目，需要 Android 文件权限（Android 11+ 可能需要"管理所有文件"） |
| 创建工作区 | 应用内部托管项目（`.linecode/project`），安全、适合测试，路径由应用管理 |
| SSH 工作区 | 远端路径，和手机本地无关；在 SSH 模式下创建/选择 |

### SAF 授权的边界

- 项目根目录一旦选定，**整个子树都可以读**；越界路径（`..`、绝对路径、跳到 `/sdcard/...`）会被沙箱策略拒绝。
- 如果项目里有大量二进制、媒体或 `.git/` 目录：在提示词里告诉 AI"忽略 `build/` `node_modules/` `*.lock`"。
- 同一项目重复选择同一目录会被识别为同一个项目，**不会**创建副本。

## 2. 模型选择策略

### 协议对比

| 协议 | 适用模型 | 适合场景 | 注意事项 |
| --- | --- | --- | --- |
| OpenAI 兼容 | 自有 OpenAI、DeepSeek、通义千问、Moonshot、第三方代理 | 默认选项，覆盖最广 | Base URL 必须能直连；公司代理要带 `Authorization` 头 |
| Codex Responses | OpenAI 新 Responses 接口（`gpt-4.1` / `o3` / `o4-mini`） | 需要更稳的工具调用、思考痕迹 | 模型 ID 不要写带日期的快照号 |
| Anthropic Messages | Claude 系列 | 长上下文、深度推理、代码审阅 | 需要 X-Api-Key 或 `Authorization: Bearer` |
| 本地 GGUF | **暂未接入** | — | 推理接口未接入，请使用云端协议 |

### 预设提供商

内置预设：DeepSeek、智谱 GLM、Moonshot Kimi、通义千问、OpenAI、Claude、Gemini、OpenRouter、Groq、Together AI、SiliconFlow、MiniMax、Ollama（`127.0.0.1:11434`）、LM Studio（`127.0.0.1:1234`）、Codex。

本机跑 Ollama / LM Studio 时选对应预设即可（localhost 明文 HTTP 是允许的）。

### 任务—模型匹配

- **短改 / 写函数 / 改单文件**：便宜的小模型（`gpt-4.1-mini` / `claude-haiku-4-5` / `deepseek-chat`），响应快、改动小。
- **跨文件重构 / 大型功能**：旗舰模型（`gpt-4.1` / `claude-sonnet-4-5` / `o3`），需要更强的计划性。
- **代码审阅 / 找 Bug**：Anthropic 系列对 diff 评审体验最好。
- **生成长文 / 文档**：OpenAI 兼容 + 长上下文。
- **多模态**（截图理解）：在"工具设置"里给图像理解单独挑一个支持图片输入的模型，可以和聊天模型不同。

> **省 token 的小技巧**：在模型列表里建好 2-3 个不同档位的模型，需要大动作时切旗舰，跑小循环时切便宜模型。用 `/model <id>` 斜杠命令秒切。

### 上下文大小与自动压缩

- 添加模型时填写**上下文大小**（支持 `128K` / `1m` / `128000`），应用以此估算用量。
- 输入框顶栏会实时显示**上下文占用百分比**，≥80% 变警告色。
- **自动压缩**：对话占用达到 50% 时，应用会自动把早期消息总结成摘要（保留最近 30% 原文）；达到 80% 时做全量压缩。压缩使用当前模型（或你配置的专用压缩模型）。
- **手动压缩**：长对话建议先让模型总结，再"更多 → 压缩上下文"：

```text
请总结当前任务状态、已改文件、未完成事项、关键约束，便于压缩上下文后继续。
```

### API Key 安全

建议：

- 不要把 Key 写进项目文件。
- 不要在聊天中粘贴真实 Key。
- 不要让 AI 读取包含 Key 的 `.env`，除非任务明确需要。
- 公司代理建议配置最小权限 Key。

### 模型列表查询

很多中转服务没有实现模型列表接口。模型列表查询失败不等于聊天不可用。

专业排障顺序：

1. 用服务商控制台确认模型 ID。
2. 在应用里选择自定义模型 ID。
3. 发送最小 prompt。
4. 再测试 tool calling。

### 工具调用次数限制

每个模型可设置单轮工具调用上限（默认 200）。长 Agent 任务如果被截断，先检查是否触顶；-1 不限，0 禁止工具。

## 3. 权限模式的取舍

| 模式 | 行为 | 适用场景 |
| --- | --- | --- |
| 只读 | 只允许读文件、搜索、分析；写文件、删除、Shell 写操作全部禁用 | 审计、规划、找 bug |
| 确认 | 每个工具调用都弹确认卡 | 改生产代码、删文件、跑未知命令之前 |
| 自动 | 已启用工具自动执行，危险工具按策略确认 | 沙箱项目 / 一次性探索 / 大量读操作 |

**实战建议**：

- 默认用"确认"，**不要**用"自动"——一旦 AI 写错 `rm -rf` 命令，**没有回头路**。
- 遇到一个长任务要连续读 10 次文件，**第一次**确认时勾选"本会话信任"，后面同类操作不再打断。
- "自动"只在**只读沙箱**（比如临时导出的演示项目）里用。
- 改完配置想回"确认"：切换权限模式立即生效，**不需要重启对话**。

**确认时检查什么**：

- 命令的 cwd 对不对。
- 命令是否删除文件。
- 是否访问网络。
- 是否安装依赖。
- 是否写入敏感路径。

## 4. 工具组合的实战套路

### 套路 A：先读后改

让 AI 先 `list_directory` + `file_read` 看相关文件 → 给出计划 → 你审阅 → 再 `file_edit` / `file_write`。**永远不要**让 AI 一上来就改文件。

推荐 Prompt：

```text
请先只读分析，不要修改文件。
输出：
1. 相关文件列表
2. 根因判断
3. 修改计划
4. 风险
我确认后再执行。
```

### 套路 B：读—改—测循环

执行阶段：

```text
按刚才计划做最小改动。
完成后运行相关测试，给出修改文件、测试命令和结果。
```

- 每个写操作都会产生 Diff 卡片，可展开查看、接受或还原。
- 让 AI 跑测试（`npm test` / `./gradlew test`）而不是口头保证。

### 套路 C：会话模式配合

- **Plan 模式**：跨文件重构前先出方案，只读不写。
- **Agent 模式**：完整工具循环，适合"探索代码库 → 定位 → 修复"长任务。
- **Chat 模式**：只聊天、快速问答。
- **控制模式**：只暴露手机控制工具（需无障碍）。

### 套路 D：长任务用 Agent / 子 Agent

- 大范围探索用 `agent` 工具（coding / explore 两种角色），主模型把子任务派出去并行跑。
- `agent_pipeline` 可以编排多阶段子任务并汇总。
- 子任务结果通过 `agent_output` 按 id 取回，避免把大量中间输出塞进上下文。

## 5. Termux 进阶

### 推荐安装与初始化

推荐 F-Droid Termux：

```bash
pkg update && pkg upgrade
pkg install openssh git nodejs python ripgrep
```

常见开发依赖：

```bash
pkg install clang make cmake pkg-config
```

### 一键对接

**设置 → 工具与执行 → Termux 对接**：页面会引导三步（安装 openssh / passwd / 启动 sshd），并提供四个按钮：复制授权指令、RUN_COMMAND 权限、打开 Termux、**自动配置 OpenSSH**（推荐，自动装 openssh、生成密钥、起 sshd、测试连接）。

### RUN_COMMAND 授权（手动）

Termux 需要允许外部应用调用：

```bash
mkdir -p ~/.termux
printf 'allow-external-apps = true\n' > ~/.termux/termux.properties
```

重启 Termux 后，Android 侧授予：

```text
com.termux.permission.RUN_COMMAND
```

如果外部调用无响应，优先检查：

```bash
cat ~/.termux/termux.properties
```

确认存在：

```text
allow-external-apps = true
```

### 访问共享存储

如果 Termux 需要访问共享存储：

```bash
termux-setup-storage
```

常见路径：

```text
~/storage/shared
/storage/emulated/0
```

注意：LineCode 的 Android 文件权限与 Termux 的 storage 权限是两套权限，不要混淆。

### 防止后台被杀

```bash
termux-wake-lock
```

并在 LineCode"保活设置"里开启 Wake Lock / 前台服务，系统设置允许 Termux 后台运行。

## 6. SSH 执行后端进阶

### 适用场景

SSH 后端适合：远程服务器开发、桌面开发机、NAS、重型构建、手机性能不足的项目。

### 最小可用环境

远端建议安装：

```bash
git
ripgrep
node / npm / pnpm
python
构建工具链
```

建立环境事实：

```bash
pwd
whoami
uname -a
git status
node -v
python --version
```

### 权限隔离

建议为 AI 创建专用用户：

```bash
sudo adduser linecode
```

生产服务器上建议：

- 禁止无密码 sudo。
- 使用独立项目目录。
- 配置磁盘配额或容器。
- 使用 Git 保护可回滚性。
- 对删除、迁移、部署命令使用 confirm。

### 私钥策略

如果使用私钥：

- 使用专用 key。
- 不复用个人主 key。
- 给 key 设置 passphrase。
- 服务端 authorized_keys 可以限制来源和命令。

### 连接排障

从另一台机器测试：

```bash
ssh -p PORT USER@HOST
```

检查：防火墙、端口映射、密码/私钥、用户 shell、服务器 sshd_config。

## 7. MCP 深入

### LineCode 的 MCP 形态

LineCode 通过 **HTTP(S)** 对接 MCP 服务（远程 MCP），不支持本地启动进程的 stdio MCP。

添加路径：**设置 → 工具与执行 → 扩展 → MCP 扩展 → 添加 MCP**。

字段：

| 字段 | 说明 |
| --- | --- |
| 名称 | 给自己看的名字 |
| HTTP/S 地址 | MCP 服务地址，必须以 `http://` / `https://` 开头 |
| 自定义请求头 | 每行一个 `名称: 值`，用于鉴权（如 `Authorization: Bearer xxx`） |
| 查询 MCP 列表 | 请求 `tools/list` 拉取工具清单，**保存前必须查询** |
| TOOLS 列表 | 逐工具开关启停 |

### 常见 HTTP MCP 服务

- 自建网关：`python -m mcp.server.sse` 之类的 HTTP/SSE 网关部署到服务器。
- 云端 MCP 网关：按服务商文档填写地址与鉴权头。
- 局域网服务：`http://192.168.x.x:8080/mcp`（同一 Wi-Fi 下可用；出站 URL 需通过沙箱策略检查）。

### 添加 MCP 前的检查

先在浏览器 / curl 里手动验证地址可访问、`tools/list` 能返回 JSON。如果服务本身不可用，应用里也不会成功。

### MCP 安全

MCP 工具能力可能很高。添加前确认：

- 它能读哪些数据。
- 它能写哪些数据。
- 是否会访问网络。
- 是否需要密钥。
- 是否有删除 / 修改能力。

首次使用建议：

```text
列出你可用的 MCP 工具，不要调用。
```

然后做只读测试。高危工具保持确认模式。

## 8. 自定义 Agent 与 Skill

### 8.1 自定义 Agent

路径：**设置 → 工具与执行 → 扩展 → Agent 扩展 → 添加 Agent**。

编辑页字段：

| 字段 | 说明 |
| --- | --- |
| 名字 | 给自己看的名字 |
| 英文标识 | 工具名（如 `test-fixer`），保存时自动规范化：小写、`a-z0-9_-`、≤48 字符 |
| 提示词 | 行为定义：角色、职责、工作方式 |
| 触发条件 | 什么场景下用这个 Agent |
| 可使用的工具 | 逐个勾选（新 Agent 默认勾选 FileReadTool + GlobTool） |
| 可使用的 MCP | 勾选已启用的自定义 MCP（builtin: / custom:） |

**让 AI 写**：编辑页第一行有"让 AI 写"入口——输入一句话需求，当前模型会起草名字、英文标识和提示词并自动回填，你再微调即可。

保存后回到工具与执行页确认对应工具组开关打开；模型即可通过 `agent` 工具调用你的自定义 Agent。

### 8.2 Skill

路径：**设置 → 工具与执行 → 扩展 → Skills 扩展**。

安装方式：

- **从 GitHub 安装**：粘贴仓库地址或 SKILL.md 直链（支持 `github.com/org/repo`、blob/tree 路径、`raw.githubusercontent.com`）。
- **选择 ZIP / SKILL.md 安装**：用系统文件选择器挑选。
- **创建 SKILL**：填名称 / 描述 / 内容（模板含 `# Skill` 和 `## 触发条件`）。
- **从本地路径安装**：输入目录 / SKILL.md / .zip 路径。

安装位置二选一：**项目**（`.linecode/skills`，随项目走）或**全局**（应用全局）。已安装的 Skill 可开关、长按修改 / 删除、多选批量删除。

### 8.3 终端提供者（IPC）

扩展页的"终端提供者"用于接入第三方 IPC Provider（如 Termux 类实现），适合需要自定义执行通道的高级场景。

## 9. 上下文与记忆

### 上下文压缩

- 手动：**更多 → 压缩上下文**，压缩前建议让模型先总结任务状态。
- 自动：50% 软触发（总结最早 70% 消息、保留最近 30% 原文）、80% 硬触发（全量压缩）。
- 压缩期间聊天流中会出现压缩进度块；压缩模型可在模型配置里单独指定（"自动"默认沿用当前模型）。

### 学习模式

**设置 → AI 行为 → 学习模式**（默认关）。开启后启用：自动 Skill 推荐、长期记忆、项目记忆、短期记忆和聊天记录检索。

### 记忆管理

**设置 → 记忆**：长期记忆 / 项目记忆 / 环境记忆 / 短期记忆（工作记忆）/ 聊天索引五个分区，带计数。

- 右上角 **＋** 添加记忆：作用域 `user`（全局）/ `project`（当前项目）/ `environment`（环境）。
- 行点击看详情（来源、范围、置信度、使用次数、时间）；长按编辑 / 删除 / 多选批量删除。
- 模型也可以主动通过 `memory_update` 工具写入用户偏好（含敏感词的内容会被拒绝）。

### 思考过程

**设置 → AI 行为**：

- 思考深度：off / auto / low / medium / high / max。
- 思考过程开关：滚动显示（默认开）、自动展开（默认关）、保留完整 reasoning（默认关）。
- 交流语气：编程模式（默认）/ 聊天模式。
- 自定义提示词：可覆盖系统提示词、语气、会话模式、学习记忆、上下文压缩模板。

## 10. 数据管理与备份

**设置 → 数据管理**：

- **导出所有数据**：导出数据库、聊天、设置和 `.linecode` 工作区为 ZIP（用系统文件选择器选保存位置）。
- **导入 .linecode**：从 ZIP 覆盖恢复数据库、聊天、配置和工作区文件。

> 导出归档会自动**脱敏**：API Key、SSH 私钥 / 密码、Web 搜索 Key、自定义 MCP 请求头都会被剥离。备份后请妥善保管文件。

建议节奏：重要项目动手前导出一次；大批量改动后导出一次。

## 11. 后台保活

**设置 → 后台保活**：

| 开关 | 说明 |
| --- | --- |
| Wake Lock（默认开） | 对话生成和压缩时保持 CPU 与屏幕唤醒 |
| 前台服务通知 | 后台任务期间显示前台服务通知（无通知权限会自动请求） |
| 假音乐播放 | 后台任务期间启动静音 AudioTrack，防止部分系统杀后台 |
| 忽略电池优化 | 跳转系统电池优化白名单 |

长任务（大批量 Agent 执行、长压缩）前建议打开前台服务 + 假音乐，配合 Termux 的 `termux-wake-lock`。

## 12. 手机控制（实验功能）

**设置 → 高级功能 → 控制手机**（标记"实验"）：

- 通过**无障碍服务**在手机本机执行点击、滑动、长按、截屏、查看界面层级、全局操作（返回 / 主页 / 最近任务等）。
- 首次使用需授权无障碍服务并同意免责声明。
- 适合：让 AI 操作你自己的 App 做 UI 测试、自动化点按。
- 注意：属于实验性能力，不同机型无障碍行为可能有差异；**控制模式**会话下才暴露手机控制工具。

## 13. 排障手册

### 13.1 模型调用失败

| 错误 | 检查项 |
| --- | --- |
| 401 | API Key、账户权限、Key 是否过期 |
| 403 | 服务商权限、模型是否开通、区域限制 |
| 404 | Base URL、模型 ID、协议路径 |
| 429 | 限流、余额、并发限制 |
| 5xx | 服务商故障、代理故障 |
| 流式断开 | 网关超时、SSE 实现、网络不稳定 |

### 13.2 Termux 无法执行

检查：

```bash
cat ~/.termux/termux.properties
which sshd
ss -ltnp | grep 8022
whoami
```

应用侧检查：

- RUN_COMMAND 权限。
- Termux 是否被系统杀后台（用 `termux-wake-lock` + 保活设置）。
- Host / Port / Username / Password。
- 执行目标是否选择了"终端提供者"或"SSH Shell"。

### 13.3 SSH 无法连接

从另一台机器测试：

```bash
ssh -p PORT USER@HOST
```

检查：防火墙、端口映射、密码/私钥、用户 shell、服务器 sshd_config。

### 13.4 文件工具异常

检查：

```bash
pwd
git status
ls -la
```

确认 workspace 是否正确；检查权限模式是否为"只读"。

### 13.5 MCP 不出现或不能调用

检查：

- HTTP/S 地址是否可访问（curl 测试）。
- 请求头是否正确。
- 是否执行过"查询 MCP 列表"（保存前必须查询）。
- 对应工具开关是否启用。
- 工具与执行页的 MCP 工具组开关是否打开。
- 服务端日志是否报错。

### 13.6 长任务被截断

检查：

- 工具调用次数限制（模型配置，默认 200）。
- 上下文是否接近上限（输入框顶栏百分比）。
- Agent 子任务是否报错。

## 14. 推荐安全基线

个人项目：

```text
权限模式：确认
执行后端：Termux 或 SSH 普通用户
项目：Git 仓库
操作前：git status
操作后：测试 + diff 审阅
```

生产服务器：

```text
权限模式：只读或确认
用户：专用低权限用户
禁止：无确认 sudo / rm -rf / 数据迁移
要求：备份、审查、回滚方案
```

MCP：

```text
先只读验证
密钥最小权限
不要把密钥写进项目
高危工具保持确认
```
