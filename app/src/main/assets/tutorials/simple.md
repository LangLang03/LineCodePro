# LineCode 零基础使用教程

> 适合对象：第一次接触 API、大模型、Termux、SSH、MCP 的用户。
> 目标：照着做，最终可以在手机里让 AI 聊天、读项目、改代码、运行命令、接入工具。

---

## 0. 先认识几个词

### LineCode 是什么

LineCode 是一个手机上的 AI 编程助手。你可以把它理解成：

- 一个聊天窗口：你在这里和 AI 对话。
- 一个模型管理器：告诉应用用哪个大模型。
- 一个项目管理器：告诉 AI 要看哪个文件夹。
- 一个命令执行器：让 AI 可以运行命令，比如 `npm test`。
- 一个工具 / MCP 管理器：给 AI 增加更多能力。

### 什么是大模型

大模型就是回答你问题的 AI，例如 OpenAI、Claude、Gemini、Qwen、DeepSeek 等。

LineCode 本身不是模型。你需要先配置一个模型，应用才能回复。

> 本地 GGUF 模型推理暂未接入，请使用云端模型（OpenAI 兼容 / Codex Responses / Anthropic Messages 协议）。

### 什么是 API Key

API Key 是服务商给你的"钥匙"。应用拿着这把钥匙去调用大模型。

请不要把 API Key 发给别人，不要截图公开，不要提交到 Git 仓库。

### 什么是 Base URL

Base URL 是大模型接口地址。

常见格式：

```text
https://api.example.com/v1
```

如果是 OpenAI 兼容接口，通常必须以 `/v1` 结尾。

错误示例：

```text
https://api.example.com
https://api.example.com/v1/chat/completions
```

原因：应用内部会按协议拼接具体请求路径，你只需要填接口根地址。

### 什么是模型 ID

模型 ID 是真正要调用的模型名称。

示例：

```text
gpt-4.1
claude-sonnet-4
qwen-plus
deepseek-chat
```

具体填什么，要看你的服务商文档或模型列表。

## 1. 第一次启动应该做什么

建议按这个顺序：

1. 进入应用。
2. 打开"设置"（聊天页右上角"更多" → 设置）。
3. 添加一个大模型（AI 与模型 → 模型管理 → 添加模型）。
4. 回聊天页，点选模型。
5. 发送一句"你好"。
6. 如果要让 AI 改代码，再配置项目（工作区）和执行环境。
7. 如果要运行命令，配置 Termux 或 SSH。
8. 如果要增加外部工具，再添加 MCP。

不要一开始就让 AI 改项目。先确认模型能正常回复。

## 2. 界面导览：认识主页、侧边栏与更多

先花两分钟把界面每个角落看一遍，后面操作就不会迷路。

### 2.1 主页（聊天页）全览

**顶部栏**（从左到右五个元素，每个都是 34dp 的点击区）：

- **☰ 菜单**：打开侧边栏（对话历史、文件树）。
- **项目名**：显示当前工作区名称（默认"LineCode"）＋下箭头。点击它 → 弹出项目列表：切换项目、打开本地项目、创建工作区、管理所有文件权限。
- **权限**（盾牌图标）：点击切换权限模式（只读 / 确认 / 自动）。
- **＋ 新建对话**：开一个新对话。
- **⋯ 更多**：教程、设置、导出对话、选择消息导出、压缩上下文、清空对话。

**消息区**（从上到下依次出现）：

- **用户气泡**：蓝色气泡，靠右，是你发送的消息。
- **AI 回复**：靠左正文，Markdown 渲染（代码块、表格、列表都支持）。
- **思考块**：`✦ 思考中` 可折叠的推理过程，滚动显示（AI 行为设置里可改自动展开）。
- **工具调用卡片**：AI 每次调用工具的记录卡，按工具类型有不同的样式：
  - 读取卡：`读取 路径`，单行展示。
  - 写入 / 编辑卡：`编辑 文件名` + 路径，待审查时带 **接受 / 还原** 按钮和"查看 diff"。
  - 终端卡：`$ 命令`，运行中转圈，完成后显示输出。
  - Agent 卡：子任务进度、嵌套工具调用。
  - MCP 卡：自定义工具名 + 输入 JSON。
- **Diff 卡片**：文件改动对比，绿色新增 / 红色删除，可展开、接受、还原。
- **通知气泡**：模型切换、压缩进度、重试等提示。
- **压缩进度块**：上下文自动压缩时显示进度。

**输入区**（从上到下）：

- **模型名**：当前模型，点击切换模型 / 查询模型列表 / 管理模型。
- **模式**：Chat / Plan / Agent / 控制（见第 5 章）。
- **上下文占用百分比**：输入框顶栏的百分比数字，≥80% 变橙色警告。
- **＋ 附件**：附加文件 / 目录作为上下文。
- **图片按钮**：附加图片（模型需支持图片输入）。
- **输入框**：输入消息；支持 `/` 斜杠命令（`/model`、`/chat`、`/plan`、`/agent` 等）。
- **发送 / 停止按钮**：空闲时是发送（↑），AI 输出中变成停止按钮（■）。

### 2.2 侧边栏（抽屉）

点顶部 **☰** 打开。左抽屉宽度 = min(屏幕宽 − 48dp, 360dp)，点背板关闭。

顶部标题：**对话历史**（对话标签页）或 **文件管理器**（文件标签页，标题右侧有刷新按钮）。

**对话标签页**：

- 顶部绿色实心按钮 **＋ 新建对话**（点击新建并关闭抽屉）。
- 列表：每条 = 图标 + 对话标题 + 时间（`M/d HH:mm`）+ 垃圾桶。
  - 点击条目 → 切换到该对话并关闭抽屉。
  - 点击垃圾桶 → 删除该对话（抽屉不关闭）。
  - 当前对话整行绿色高亮。
  - 空态："暂无对话记录"。

**文件标签页**：

- **项目条**：显示当前项目名（粗体）+ 路径（最多 2 行省略）。
  - **长按项目条**（有触觉反馈）→ 弹窗"移除工作区"：从已打开目录中移除该项目（**不会删除真实目录**），按钮"取消 / 删除"。
- **文件树**：目录可展开 / 收起；文件图标按扩展名着色（.java/.kt/.js/.ts/.xml/.json/.gradle 黄色代码图标，.md/.txt/.log 文本图标，其他灰色）。
  - 点击文件 → 打开 / 读取。
  - 长按文件或目录 → 操作菜单（重命名、复制、删除、新建文件 / 文件夹等）。
  - **根节点行尾的 ＋ 按钮** → 新建文件 / 文件夹。
  - 未加载时显示"正在准备目录…"。

### 2.3 更多菜单

点顶部 **⋯**：

| 菜单项 | 作用 |
| --- | --- |
| 教程 | 打开本教程（简单 / 专业两版） |
| 设置 | 进入全部设置 |
| 导出对话 | 把当前对话导出为 Markdown / 分享 |
| 选择消息导出 | 多选若干条消息合并导出 / 分享 |
| 压缩上下文 | 手动把早期上下文总结为摘要（省 token） |
| 清空对话 | 清空当前对话（不删模型和项目） |

## 3. 接入在线大模型

### 3.1 打开添加模型页面

路径：

```text
聊天页 → 右上角"更多" → 设置 → AI 与模型 → 模型管理 → 添加模型（右上角 ＋）
```

也可以直接点聊天输入框上方的模型名称，在弹窗里点"⚙ 管理模型"。

### 3.2 添加模型：方式选择页

进入"添加模型"后有两种方式 + 预设列表：

- **自定义模型**：进入原添加页，手动选择协议并填写 Base URL、模型 ID 和密钥。
- **加载本地模型**：GGUF 本地推理入口（**当前未接入**，表单里的文件选择器提示"稍后接入"，保存按钮不可用）。
- **预置提供商**：内置 17 个一键预设，选择后自动填好 Base URL 与协议，你只需补 API Key 和模型 ID：

| 预设 | 协议 | 预填 Base URL |
| --- | --- | --- |
| DeepSeek | OpenAI 兼容 | https://api.deepseek.com/v1 |
| GLM（智谱） | OpenAI 兼容 | https://open.bigmodel.cn/api/paas/v4 |
| Mimo（小米） | OpenAI 兼容 | https://api.xiaomimimo.com/v1 |
| Mimo Token 计划 | OpenAI 兼容 | https://token-plan-cn.xiaomimimo.com/v1 |
| Kimi（Moonshot） | OpenAI 兼容 | https://api.moonshot.cn/v1 |
| Qwen（DashScope） | OpenAI 兼容 | https://dashscope.aliyuncs.com/compatible-mode/v1 |
| OpenAI | OpenAI 兼容 | https://api.openai.com/v1 |
| Claude | Anthropic | https://api.anthropic.com |
| Gemini | OpenAI 兼容 | https://generativelanguage.googleapis.com/v1beta/openai |
| OpenRouter | OpenAI 兼容 | https://openrouter.ai/api/v1 |
| Groq | OpenAI 兼容 | https://api.groq.com/openai/v1 |
| Together AI | OpenAI 兼容 | https://api.together.xyz/v1 |
| SiliconFlow（硅基流动） | OpenAI 兼容 | https://api.siliconflow.cn/v1 |
| MiniMax | OpenAI 兼容 | https://api.minimax.chat/v1 |
| Ollama（本机） | OpenAI 兼容 | http://127.0.0.1:11434/v1 |
| LM Studio（本机） | OpenAI 兼容 | http://127.0.0.1:1234/v1 |
| Codex | Codex | https://api.openai.com/v1 |

> 本机跑 Ollama / LM Studio 时选对应预设即可（localhost 明文 HTTP 是允许的）。

### 3.3 添加 / 修改模型表单：每个字段

顶部右侧有 **测试** 和 **保存** 两个按钮（本地模式隐藏测试、保存恒禁用）。

**提供商**：4 个胶囊按钮 **OpenAI / Codex / Anthropic / 本地**。
- 从预设或编辑进入时协议已锁定（其他协议置灰）。
- 点"本地"会提示"请从『加载本地模型』进入本地模型表单"——本地模型暂未接入。

**名称**：给你自己看。可留空（预设模式），保存时自动用模型 ID。

**Base URL**：接口根地址。
- OpenAI 兼容：以 `/v1` 结尾；Codex：不要加 `/responses` 或 `/chat/completions`；Anthropic：以 `/anthropic` 结尾。
- 留空时回退预设地址或协议默认值（OpenAI/Codex → `https://api.openai.com/v1`，Anthropic → `https://api.anthropic.com`）。

**API Key**：密码框（显示为星号）。Anthropic 协议用 X-Api-Key 或 `Authorization: Bearer`。

**模型 ID**：
- 默认是"请先查询并选择模型"＋**查询**按钮（需要 Base URL 和 API Key 都填了才能点）。查询成功会弹出"选择模型"列表，底部有"自定义 ID…"选项。
- 查询失败不代表不能用——打开右侧 **自定义** 开关，手动输入模型 ID（编辑模型时默认就是自定义输入）。

**工具调用次数限制**：数字，默认 **200**。`-1` = 不限制；`0` = 禁止工具调用；其他数字 = 单轮最多调用次数。

**上下文大小**：如 `128K`、`1m`、`128000`（支持 k / m 单位）。留空则用模型默认。应用用这个值计算何时自动压缩。

**专用压缩模型**（仅 OpenAI 兼容 / Codex 协议显示，Anthropic / 本地隐藏）：
- 总开关默认 **关**；开启后自动压缩时优先用提供方的压缩模型（OpenAI/Codex 走 Responses 压缩路径）。
- 开启后出现"自动"开关（默认 **开**，沿用当前模型）；关掉自动后可以查询或手输"压缩模型 ID"（不填则保存被阻止）。

**保存**：校验失败会有对应提示（"请填写名称和模型 ID" / "请填写 API Key" / "工具调用次数限制只能是 -1 或大于等于 0 的整数" / "请选择或填写压缩模型 ID"）。保存成功自动把该模型设为当前聊天模型。

### 3.4 保存并测试

1. 点"测试"确认连通性（可选；结果有成功 / 失败详情）。
2. 点保存。
3. 回模型列表，点选刚添加的模型（打勾即当前聊天模型）。
4. 回聊天页，发送：

```text
你好，请用一句话回复我。
```

### 3.5 常见错误

| 现象 | 原因与检查 |
| --- | --- |
| 401 / 403 | API Key 错 / 过期 / 无权限 / 余额不足；检查是否复制完整、有无空格、模型是否开通 |
| 404 | Base URL 多写了 `/chat/completions`、OpenAI 兼容没以 `/v1` 结尾、模型 ID 不存在 |
| 查询模型失败 | 中转服务可能不支持模型列表接口；改用"自定义 ID"手输即可 |
| 429 / 5xx | 限流 / 余额 / 服务商故障 |

## 4. 选择工作区（项目）

### 4.1 项目是什么

项目就是 AI 读写文件的工作目录。

如果项目选错，AI 可能会看错文件、改错文件。

### 4.2 打开项目

点击聊天顶部**项目名**，弹出项目列表：

- **打开本地项目**：通过系统文件选择器（SAF）选择项目根目录，适合真实开发。Android 11+ 可能要求"管理所有文件"权限，按引导授权。
- **创建工作区**：在应用内部创建托管项目（`.linecode/project` 下），适合测试，路径由应用管理。
- **管理所有文件权限**：访问外部存储需要时在这里打开。

选过的目录会一直保留在列表里，随时切换；侧边栏文件页**长按项目条**可移除（不删真实目录）。

### 4.3 每次开始任务前先确认目录

建议对 AI 说：

```text
先只读检查当前项目目录，运行 pwd 和列出根目录文件，不要修改任何文件。
```

确认无误后再继续。

## 5. 开始对话

### 5.1 发送第一条消息

例如：

- "阅读 `src/main/java/...` 下的 5 个文件，告诉我这个模块的职责。"
- "重构 `Foo.java`，加单元测试。"
- "用 Web 搜索查一下 Android 16 的新特性并整理成 Markdown。"

### 5.2 附加文件

输入框左侧 **＋** 附加文件 / 目录（本地、SSH、Termux 均可）；右侧图片按钮附加图片（模型需支持图片输入）。

### 5.3 工具调用卡片与 Diff

工具调用以**卡片**形式出现在回复中，可展开查看参数、运行日志、产物。

文件改动产生 **Diff**（编辑卡片上"查看 diff"），可**接受**或**还原**。

### 5.4 会话模式

输入框下方切换：

| 模式 | 行为 |
| --- | --- |
| Chat | 只读分析、聊天（不执行写操作） |
| Plan | 只读规划、给方案 |
| Agent | 完整工具循环，可读写文件、跑命令（默认） |
| 控制 | 仅手机控制工具（需无障碍服务） |

### 5.5 斜杠命令

```text
/chat /plan /agent /control        # 切换模式
/model <id>                        # 快速切换模型
/model <id> low|medium|high|max    # 切换模型并设置思考深度
```

## 6. 权限详解：权限模式与确认卡片

### 6.1 三种权限模式

顶部盾牌图标（或工具与执行页）切换：

| 模式 | 行为 | 适合场景 |
| --- | --- | --- |
| 只读 | 只读文件、搜索、分析；写文件、Shell 写操作全部禁用 | 看代码、找 bug、给方案 |
| 确认 | 危险操作弹确认卡片，同意后才执行 | 日常使用，**新手建议默认** |
| 自动 | 已启用工具自动执行，危险工具按策略确认 | 非常清楚任务风险、项目有 Git 可回滚 |

### 6.2 工具确认卡片怎么读

"确认"模式下，AI 每次执行工具都会先弹一张**工具卡片**，状态"等待确认"，上面显示工具名、参数（写入路径 / 命令）、必要时附 Diff 预览。

以**写入文件**为例，两个按钮语义很重要：

- **接受（同意）**：**文件已经写进去了**——同意不是"允许去写"，而是"我看了内容，接受这次修改"。接受后这次写入生效，应用不再干预。
- **还原（拒绝）**：**撤销这次写入**——应用基于记录的 Diff 把文件恢复到写入前的样子。

> 看到写入卡时，先展开"查看 diff"确认改动内容，再决定接受还是还原。

**Shell 命令卡片**同理：显示命令，接受 = 运行，拒绝 = 不运行。

**本会话信任**：部分确认卡可勾选，勾选后本对话内同类工具不再弹确认。

### 6.3 危险操作

删除文件、越界路径、明文 HTTP 等即使"自动"模式也按策略确认或拒绝。

## 7. 配置 Termux，让 AI 在手机本机运行命令

### 7.1 Termux 是什么

Termux 是 Android 上的 Linux 命令行环境。配置好后 AI 可在手机本机执行 `pwd`、`npm test`、`python script.py` 等命令。

### 7.2 安装与初始化

安装 F-Droid 版 Termux，打开执行：

```bash
pkg update && pkg upgrade
pkg install openssh git nodejs python ripgrep
```

做 Android / Node 项目通常还要：`pkg install clang make cmake`。

### 7.3 在 LineCode 里对接 Termux

路径：**设置 → 工具与执行 → 工具与执行 → 执行目标选择"终端提供者"或"SSH Shell" → 打开"Termux 对接"**。

对接页引导三步：1) `pkg install openssh`；2) `passwd` 设密码；3) 启动 sshd（端口 **8022**）+ 开启 Termux:Wake Lock。

页面四个按钮：

- **复制授权指令**：复制 `allow-external-apps = true` 写入命令，回 Termux 粘贴执行。
- **RUN_COMMAND 权限**：向系统申请 `com.termux.permission.RUN_COMMAND`。
- **打开 Termux**：一键唤起。
- **自动配置 OpenSSH**（推荐）：自动装 openssh、生成密钥、起 sshd、测试连接（最长 15 分钟）。

### 7.4 手动配置 SSH（可选）

```text
Host: 127.0.0.1
Port: 8022
Username: Termux 里 whoami 的输出
Password: 你 passwd 设置的密码
```

保存后"测试连接"。

### 7.5 测试命令

对 AI 说："请运行 pwd，然后告诉我当前目录。" 确认卡片只运行 `pwd` 后允许。

### 7.6 防后台被杀

Termux 里 `termux-wake-lock`；LineCode"保活设置"开 Wake Lock / 前台服务；系统设置允许 Termux 后台。

## 8. 配置远程 SSH

### 8.1 什么时候用

代码在电脑 / 服务器 / NAS 上、手机性能不够、依赖太大、要跑构建或后端服务时。

### 8.2 填写连接信息

路径：**设置 → 工具与执行 → 工具与执行 → 执行目标"SSH Shell" → SSH 连接设置**。

| 字段 | 说明 |
| --- | --- |
| Host | 服务器 IP 或域名 |
| Port | SSH 端口，通常 22；Termux 是 8022 |
| Username | 用户名 |
| Password（可选） | 密码登录 |
| Private key（可选） | 私钥登录，粘贴 `-----BEGIN OPENSSH PRIVATE KEY-----` 内容 |

### 8.3 保存并测试

先"保存配置"，再"测试连接"。成功后回项目列表选择或创建 SSH 工作区。

### 8.4 连接后先做的测试

```bash
pwd

whoami
git status
```

确认目录、用户、项目都正确，再让 AI 动文件。

### 8.5 安全建议

给 AI 单独建用户、不给 root 密码、默认禁 sudo、重要项目先有 Git 记录、改文件前先要计划。

## 9. 添加 MCP 工具

### 9.1 MCP 是什么

MCP 可以理解为"给 AI 装工具插件"：查数据库、控制浏览器、访问服务、调用你的 HTTP 服务等。

LineCode 通过 **HTTP(S)** 对接远程 MCP 服务（不支持本地启动进程的 stdio MCP）。

### 9.2 添加 MCP 的步骤

路径：**设置 → 工具与执行 → 扩展 → MCP 扩展 → 添加 MCP**。

1. **名称**：给自己看的名字（如"公司 MCP 服务"）。
2. **HTTP/S 地址**：必须以 `http://` 或 `https://` 开头，例如 `https://example.com/mcp`、`http://192.168.1.10:8080/mcp`。
3. **自定义请求头（可选）**：点"添加请求头"，每行"名称 / 值"，如 `Authorization: Bearer xxxxx`。
4. 点 **"查询 MCP 列表"**：应用请求服务的 `tools/list`。**新建 MCP 必须先查询成功才能保存**；查询失败会提示原因。
5. 在 **TOOLS 列表 · 已启用 N** 里逐个开关想用的工具。
6. 保存。

保存后回"工具与执行"页，确认对应工具组开关打开；模型即可调用这些工具。

### 9.3 测试与安全

先让 AI "列出你可用的 MCP 工具，不要调用"，再做只读测试。确认 MCP 的读写能力、网络行为、密钥需求后再放开；高危工具保持"确认"模式。

1. **选择 ZIP / SKILL.md 安装**：系统文件选择器（仅接受 `.zip` / `.md`），选后弹"安装到"：当前工作区 `.linecode/skills`（随项目保存和导出）/ 应用全局 `.linecode/skills`（**默认勾选项目**）。

4. **从本地路径安装**：手动输入目录、SKILL.md 或 .zip 路径（默认路径 `/storage/emulated/0/Download/skill.zip`）。
5. **多选**：批量删除（"此操作不可撤销"）。

已安装列表：行描述"位置 · SKILL.md 路径"（项目 / 全局 / SSH），Switch 启停；长按进入多选。

## 23. 设置详解：数据管理

路径：**设置 → 数据与系统 → 数据管理**。

- **导出所有数据**：导出数据库、聊天、设置和 `.linecode` 工作区为 ZIP（系统文件选择器选保存位置）。
- **导入 .linecode**：从 ZIP 覆盖恢复数据库、聊天、配置和工作区文件。

> 导出归档自动**脱敏**：API Key、SSH 私钥 / 密码、Web 搜索 Key、自定义 MCP 请求头都会被剥离。

## 25. 设置详解：后台保活

路径：**设置 → 数据与系统 → 后台保活**。

**编码任务保活**（三个开关，任一开启启动保活服务，全关停止）：

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| Wake Lock | **开** | 对话生成和压缩时保持 CPU 与屏幕唤醒 |
| 前台服务通知 | 关 | 开启后常驻显示"正在编码"通知（需通知权限） |
| 假音乐播放 | 关 | 后台任务期间启动静音 AudioTrack，防系统杀后台 |

**系统白名单**：

- **忽略电池优化**：打开 Android 电池优化白名单申请页面（状态只读，跟随系统）。

长任务（大批量 Agent 执行、长压缩）前建议打开前台服务 + 假音乐。

## 28. 推荐新手工作流

### 让 AI 看代码

```text
请先只读分析这个项目结构，不要修改文件。告诉我主要目录和启动方式。
```

### 让 AI 修 bug

```text
请先定位问题，不要修改文件。找到原因后给我修改计划，我确认后再改。
```

### 让 AI 修改代码

```text
请按最小改动修复这个问题。修改前说明会改哪些文件。修改后运行相关测试。
```

### 让 AI 运行命令

安全命令示例：`pwd`、`ls`、`git status`、`npm test`。
需要谨慎的命令：`rm -rf`、`sudo`、`curl ... | sh`、`chmod -R`、`mv 大范围目录`。

## 29. 出问题怎么排查

### AI 不回复

检查：是否选择了模型、API Key / Base URL / 模型 ID 是否正确、网络可用、服务商欠费 / 限流。

### AI 不能运行命令

检查：Termux / SSH 是否配好、连接测试是否通过、权限模式是否"只读"、Termux 是否被后台杀、远程机器是否可达。

### AI 改错地方

立刻停止，让它执行 `pwd` 和 `git status` 确认目录；有 Git 可以回滚。

### 写入的文件不满意

在对应写入 / 编辑卡片上点 **还原**（基于 Diff 撤销）；或让 AI 再改一版。

### 工具卡片一直"运行中"

检查模型是否还在输出、工具调用次数限制是否过小、网络请求是否卡住。

## 附：隐私与安全提示

- **网络访问**：所有出站 URL 经沙箱策略检查，明文 HTTP 仅允许 `localhost / 127.0.0.1 / 10.0.2.2`。
- **私密数据**：导出归档自动脱敏，但仍请妥善保管。
- **存储权限**：选项目时系统要求 SAF 授权；失败去 系统设置 → 应用 → LineCode → 存储 重新授权。
- **遇到崩溃 / Bug**：`设置 → 关于` 看版本号，配合 `设置 → 错误日志` 反馈。
